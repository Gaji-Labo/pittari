# 0001 撮影中の Chrome の通信先を絞る

状態: 採用（#35、#38）

## 背景

`design-diff` の Chrome はサンドボックスの外で動き、ページのコードは AI が書く。撮影中のページが外部へ通信できると、承認画面に出ない宛先へ、AI が読んだ内容を送れる。

一方で、外部の Web フォントなどを読み込むプロジェクトでは、外部への通信を止めると描画が見本と変わり、差分を正しく測れない。

## 決定

- 撮影中の通信先を、開発サーバーと、`--allow-domain` で渡したホストに限る
- `--allow-domain` はホスト名だけを受け付ける。ワイルドカードやポートを受け付けると、承認画面に並ぶ文字列から、許可する範囲を人が読み取りにくくなる
- `--allow-domain` を付けた実行は、auto mode でも人の承認画面に回す。auto mode では判定役のモデルが人の代わりに承認するので、hook が無ければ、人が宛先を見ないうちに外部との通信が許可される
- 承認した宛先は、同じセッションの間だけ覚える。調整のたびの再実行で、同じ宛先を尋ね続けないため
- セッションを終えたら、承認した宛先を忘れる。日をおいて再開したセッションで、承認した経緯を人が覚えていない宛先や、その後に持ち主が変わった宛先を、尋ねずに使わないため

## 採らなかった案

- 許可する宛先を、プロジェクトの設定ファイルや `.design-diff/` に置く: AI がサンドボックスの中から書き換えられる。防ぐには利用者が書き込みを止める設定を入れる必要があり、入れ忘れを `design-diff` が検知できない
- ユーザー設定（`~/.claude/settings.json`）の `sandbox.network.allowedDomains` を読む: 他のプロジェクトでしか許可していない宛先まで、すべてのプロジェクトで許可される
- 許可する宛先をプラグインに組み込む: 受託開発で使う書体のサービスを限れない
- 外部への通信をすべて止めて、遮断したホストを報告するだけにする: 外部の書体を使うプロジェクトでは、描画が見本と変わって正確に測れない
- Claude Code の permissions の ask ルールで承認を求める: ask ルールは承認を覚えないので、再実行のたびに尋ねる
