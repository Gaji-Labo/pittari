# 0002 サンドボックスの外で動く design-diff の入出力を限る

状態: 採用（#34、#37、#39）

## 背景

Chrome はサンドボックスの中では起動しないので、README の導入手順で `design-diff` をサンドボックスの除外ルールに入れている。そのため `design-diff` はサンドボックスの外で動く。Stop hook も、Claude Code の hook としてサンドボックスの外で動く。一方で、引数と `.design-diff/` の中身は、サンドボックスの中の AI が決められる。そのままでは、AI は引数や `.design-diff/` を通して、サンドボックスが禁じているコマンドを実行したり、禁じている場所を読み書きしたりできる。

## 決定

- 引数で受け取った文字列をコマンドとして実行しない。`--build` は廃止した。`--build` を渡されたときは、ビルドを先に単独で実行するよう伝えて、エラーで終える。単独で実行したビルドは、サンドボックスの中で動く
- `--url` に渡せるのは、ホスト名が `localhost`・`127.0.0.1`・`[::1]`・`*.localhost` の `http:` か `https:` の URL だけにする。サンドボックスの外で動く Chrome に、`file:` のファイルや外部のページを開かせないため
- `--metadata`・`--texts` で渡されたファイルは、`.design-diff/inputs/` の下にあるものだけを読む。渡されたパスをそのまま読むと、サンドボックスが読むのを禁じている場所のファイルの中身が、`layout.json` や報告に出る
- `--design` で渡されたファイルは、置き場所を問わず読む。PNG として読めないファイルは、中身を出さずにエラーで終える。また AI は、サンドボックスが禁じている場所のファイルを読めないので、そのファイルを PNG に作り変えて渡すこともできない
- `.design-diff` の中のリンクをたどって読み書きしない。`design-diff` がパスを確かめてから読み書きするまでの間に、AI がパスをリンクへ差し替えた場合も、リンク先を読み書きしない
- Chrome はサンドボックスを有効にして起動する。`design-diff` は Claude Code のサンドボックスの外で動くので、Chrome 自身のサンドボックスまで外すと、撮影中のページのコードが Chrome の脆弱性を 1 つ突くだけで、ユーザーの権限でファイルを読んだりコマンドを動かしたりできる

## 採らなかった案

- `--build` を受け取って何も実行せずに続ける: AI がビルド前の描画を測り、調整が効かなかったと誤って判断する
